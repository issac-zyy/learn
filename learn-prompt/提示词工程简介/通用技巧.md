# 通用技巧

首先：提示词是需要不断迭代的，需要经过大量的实验才能得到最佳的结果

一味地堆砌各种技巧不一定会是最佳结果



当遇到一个大任务的时候，需要拆分为多个简单的小任务，并随着结果的改善逐步构建

## 指令

可以使用指令来指示模型执行各种简单的任务

建议将指令放在提示的开头。同样，也建议是使用像“###”这样的清晰分隔符来分隔指令和上下文

```bash
### 指令 ###
将以下文本翻译成西班牙语：

文本：“hello！”
```

## 具体性

提示词越是具体，结果就越好，特别是对生成的结果或者风格有要求的时候，这一点尤为重要

同时，还应注意提示的长度，因为提示的长度是有限制的。细节太多，不一定是最好的办法

## 避免不确定性

不需要非常聪明的表达，而是应该要明确，具体的表达

## 做什么和不做什么

不要让llm不做某件事，而是让ai做某件事

以下是一个电影推荐聊天机器人的示例，因为我写的指令——关注于不要做什么，而失败了。

*提示：*

```
以下是向客户推荐电影的代理程序。不要询问兴趣。不要询问个人信息。客户：请根据我的兴趣推荐电影。代理：
```

*输出：*

```
当然，我可以根据你的兴趣推荐电影。你想看什么类型的电影？你喜欢动作片、喜剧片、爱情片还是其他类型的电影？
```

以下是更好的提示：

*提示：*

```
以下是向客户推荐电影的代理程序。代理负责从全球热门电影中推荐电影。它应该避免询问用户的偏好并避免询问个人信息。如果代理没有电影推荐，它应该回答“抱歉，今天找不到电影推荐。”。```顾客：请根据我的兴趣推荐一部电影。客服：
```

*输出：*

```
抱歉，我没有关于你兴趣的任何信息。不过，这是目前全球热门的电影列表：[电影列表]。希望你能找到喜欢的电影！
```

上述示例中的一些内容摘自 ["Best practices for prompt engineering with OpenAI API" article.](https://help.openai.com/en/articles/6654000-best-practices-for-prompt-engineering-with-openai-api)
